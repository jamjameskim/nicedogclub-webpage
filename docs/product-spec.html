#1. 문서 목적

우쥬산책(Would You Walk)은 반려견과의 일상적인 산책을 기록하고, 공공데이터 기반 쓰레기통 위치를 지도에서 안내하며, 반려견 분실 시 마지막 위치와 같은 동네 사용자에게 신속히 알리고 목격 정보를 보호자에게 전달하는 지역 기반 서비스다. 여기에 산책으로 마주친 이웃과 이어지는 소셜 기능(동네친구·친한친구 모임·하트)을 더해, 위급할 때만 열게 되는 앱이 아니라 매일 열 이유를 만든다.

이 문서는 화면 구현에 필요한 값과 상태뿐 아니라 실제 서비스 운영에 필요한 위치·알림·개인정보·신뢰·신고·장애 대응 기준까지 정의한다. 별도 표시가 없는 수치와 정책은 실제 반영된 값이며, 코드 안의 상수가 최종 근거다 — 이 문서와 코드가 어긋나면 코드가 맞다.

#2. 제품 목표와 원칙

2.1 목표

  1. 사용자가 별도 학습 없이 2탭 이내로 산책을 시작하게 한다(홈 화면 FAB).
  2. 산책 기록에서 생성되는 위치·사진·시설 정보를 일상적 효용으로 돌려준다.
  3. 분실 신고 등록 후 곧바로 같은 동 이웃에게 알림 발송을 완료한다.
  4. 목격자가 앱이 없어도 링크 하나로 위치·시각·사진을 보호자에게 전달하게 한다(콜드스타트 대응).
  5. 신고자의 정확한 집 주소나 목격자의 현재 위치가 불필요하게 공개되지 않게 한다.
  6. 산책이라는 행동 자체에 사회적 보상(하트·동네친구)을 붙여 위급 상황이 아니어도 앱을 열 이유를 만든다.

2.2 핵심 원칙

  • 긴급 기능 우선: 활성 분실 신고(내 신고 또는 진행 중인 산책)는 홈의 하트·날씨·통계보다 위에 노출한다.
  • 입력보다 확인: 반려견 프로필을 분실 신고서에 자동 채우고, 사용자는 확인·수정만 한다.
  • 최소 공개: 지도에는 근사 위치를 표시하고 정확 좌표는 권한과 목적에 따라 제한한다.
  • 행동 중심 문구: 제보하기보다 목격했어요, 종료보다 찾기 완료처럼 결과가 분명한 CTA를 사용한다.
  • 안전 우선: 목격자에게 접근·추격·포획을 요구하지 않고 거리 확보와 보호자 연락을 안내한다.
  • 판단 가능한 정보 제공: 쓰레기통은 공공데이터와 없어졌어요 누적 수만 제공하고, 이용 가능 여부는 사용자가 판단한다.
  • 실패는 실패로 보여준다: 위치를 못 잡았거나 데이터를 못 가져왔을 때 그럴듯한 기본값으로 대체해 안심시키지 않는다.
  • 관계가 걸린 쓰기는 우회 못하게 한다: 하트 주기·모임 가입·동네친구 매칭 기록처럼 "정말 그 관계인지" 확인이 필요한 쓰기는 SECURITY DEFINER 함수로만 허용한다.

2.3 실제 구현 범위 (v2.0 기준)

  • 카카오/구글 로그인, 필수 약관 동의
  • 반려견 1마리 등록 및 수정(계정당 1마리 전제로 확정, 데이터 모델은 배열이라 확장 여지는 남김)
  • 산책 시작·일시정지·재개·종료, 경로·시간·거리·사진 저장. 완료 화면에서 바로 제목·메모·사진 추가
  • 산책 중 공공데이터 기반 쓰레기통 지도 조회 및 없어졌어요 제보 수 확인
  • 분실 신고 생성·게시·갱신·종료, 4단계(반려견 확인 → 목격 정보 → 자주 다니던 곳 노출 여부 → 게시)
  • 동 기반 분실 푸시 알림 및 인앱 상세(반경 방식 폐기)
  • 목격 제보 생성(앱 사용자 + 비회원 웹 링크 둘 다), 보호자 실시간 반영, 결과 알림 구독
  • 사진 모아보기, 산책 기록 목록/캘린더, "자주 갔던 곳" 히트맵
  • 주변 분실 지도(내 동네/전체보기 토글), 내 활동, 알림·공개 범위·차단 설정
  • 콘텐츠 신고, 차단(양방향 RESTRICTIVE 정책으로 완전 비노출)
  • 동네친구(경로 매칭) · 친한친구 모임(초대코드)
  • 하트(좋아요) — 동네친구·모임 멤버 사진에 하루 1회, 산책 1km당 1개 자동 적립
  • 리텐션 푸시 — 하루 1회 다이제스트(6트리거 우선순위) + 개인화된 산책 리마인더

2.4 후속 범위

  • 실시간 채팅·전화번호 중계 통화
  • 동물병원·보호소·경찰/지자체 연계
  • AI 사진 유사도 검색
  • 배지·리워드, 웨어러블 연동
  • 쓰레기통 외 배변봉투함·급수대·반려견 출입 시설
  • 분석 이벤트 트래킹, 운영자 웹 콘솔
  • Android 출시

  1. 인사 + 분실 신고 버튼(사이렌) + 알림함
  2. 진행 중인 산책 배너(있으면)
  3. 내 분실 신고 현황(위치·동과 무관하게 항상 표시) 또는 우리 동네 분실 배너
  4. 반려견 사진·이름 + 하트(받은 좋아요 + 산책 거리 기반 합산)
  5. 최근 추억(사진 가로 스크롤)
  6. 산책 날씨
  7. 캘린더("산책기록", "전체보기"로 상세 대시보드 이동)
  8. 이번 주 통계
  9. 산책 시작/이어보기 — 화면 하단 FAB

동네친구 미리보기·최근 산책 목록은 뺐다(각각 친구 탭·기록 탭에 이미 있음). 산책 시작만 항상 접근 가능한 FAB로 뗐다.

8.2 하트 배너

반려견 이름 옆 하트 알약을 누르면 "친구들이 하트를 눌러주거나, 산책을 하다보면 하트가 쌓여요" 팝업이 뜬다. 자세한 규칙은 §9.7.

8.3 산책 날씨

날씨 요약, 기온, 좋음/나쁨 판단. 위치 미동의/API 실패 시 현재 날씨를 불러올 수 없어요만 표시하고 산책은 막지 않는다.

#9. 산책 기록

9.1 시작 전 / 권한

반려견 미등록이면 시작을 막고 등록으로 유도한다. 위치 권한이 "사용 중에만"이면 경고 배너를 띄우고, 설정에서 "항상 허용"으로 올리면 앱이 포그라운드로 돌아올 때 자동 감지해 백그라운드 추적으로 승격한다.

9.2 산책 중 화면

상단 고정 지표(경과 시간·거리), 지도(현재 위치·경로), 하단 원형 버튼(일시정지/재개·종료·카메라), 쓰레기통 위치 보기 토글. 화면을 나가도 추적은 계속된다 — 탭 바 위 진행 상황 바가 항상 뜬다.

9.3 거리 및 경로 계산

  1. 정확도 25m 초과, 속도 10m/s 초과 픽스는 버림
  2. 3m 미만 이동은 GPS 지터로 보고 좌표를 안 쌓음
  3. 유효 좌표 간 haversine 거리 누적
  4. 일시정지 구간은 거리·시간에서 제외
  5. 위경도 델타 60도 초과 경로는 렌더링 시 클램프(네이티브 지도 크래시 방지)

9.4 종료

요약 화면에서 바로 제목·메모·사진을 추가할 수 있다(v2.0 신규). "즐거웠어요"를 누르면 저장 전/후 총 거리를 비교해 늘어난 하트 개수를 계산하고, 1개 이상이면 하트 애니메이션을 보여준다. 경로 2점 미만이면 저장하지 않는다.

9.5 진행 중 산책의 생존성

iOS가 프로세스를 죽였다가 위치 이벤트로 headless 재기동될 때, 진행 중 산책 정보가 메모리에만 있어 사라지는 문제가 있었다. 지금은 경량 로컬 스냅샷으로 남겨두고 재기동 시 복원한다. 죽어있던 구간의 이동 자체는 복구 불가능하다 — "잃지 않는" 안전망이지 "메워주는" 게 아니다.

9.6 산책 리마인더 (신규, 개인화 푸시)

  • 최근 산책 3건 이상이면 본인 최근 산책 시작 시각의 평균(KST)에 맞춰, 그 시각에 오늘 산책이 없으면 발송. 버퍼를 안 두는 이유 — 늦게 보낼수록 "이미 걸었는데 기록만 깜빡한" 사람을 잘못 찌를 확률이 올라간다.
  • 3건 미만(신규)이면 09시 고정.
  • 지금 산책 중이면 스킵(서버에 시작/종료 신호를 보냄, 4시간 넘은 신호는 무시).
  • 오늘 산책 했으면 22시에 축하 메시지 한 번.
  • 15분 주기 크론이 판정.

9.7 하트(좋아요)

  • 총 하트 = 받은 좋아요(서버 저장) + 걸은 총 거리 1km당 1개(매번 계산, 저장 없음).
  • 친구 탭에서 상대 사진 확대 → 하트 버튼. 하루에 같은 상대에게 한 번만, 총량 제한 없음.
  • 자기 자신에게는 못 준다. 관계 확인(동네친구 또는 같은 모임)은 서버 함수 안에서만.
  • 받으면 즉시 상대에게 푸시("{이름}가(이) 하트를 눌렀어요!").

#10. 쓰레기통 지도

v1.2 초안과 대부분 동일하게 구현됐다.

10.1 지도 표현

주변/산책 오버레이에서 쓰레기통 레이어를 토글한다. 공공데이터 기반 위치만 표시, 사용자 추가·수정 불가. 제보가 누적돼도 핀을 자동으로 안 숨긴다.

10.2 시설 상세 / 없어졌어요 제보

거리·유형·주소·출처 표시, 값 없으면 정보 없음. 유일한 CTA는 없어졌어요, 동일 시설 24시간 1회 제한, 10초 실행취소.

#11. 분실 신고 — 보호자 플로우

11.1 진입

홈의 사이렌 버튼, 분실 배너에서 진입. 이미 활성 신고가 있으면(위치 무관하게 항상 감지) 그 화면으로 보내 중복 신고를 막는다.

11.2 1단계: 반려견 확인

등록된 프로필에서 이름·사진·견종·성별·나이·체중·특징을 자동 채운다.

11.3 2단계: 마지막 목격 정보

위치(지도 확정 시 동네 이름도 함께 역지오코딩), 시각(TimePicker), 사람을 경계하는지 여부.

11.4 3단계: 자주 다니던 곳 노출 (신규 단계)

산책 경로를 약 11m 격자로 뭉친 빈도표를 노출할지 선택(기본값 켬). 목격자·보호자 화면에 히트맵으로 표시되고, 찾기 완료 시 서버에서 실제로 삭제된다.

v1.2의 "알림 반경(1/3/5km) 선택"은 없다. 신고 시점의 "동"으로 자동 결정된다.

11.5 수신 대상 계산

같은 동인 사용자 전원. 상대 프로필의 동 값은 그 사람이 최근 앱을 열었을 때 있던 곳이다(집 동네 고정값 아님). 차단 관계면 어느 방향으로도 노출 안 됨.

11.6 진행 중 사건 관리

지도에는 마지막 목격 지점(검정 핀)과 제보 순서(주황 번호 핀) — 색을 다르게 줘서 같은 지점 근처일 때도 구분되게 했다. 헤더 아래 "링크 복사" 띠배너로 게스트 제보 링크를 외부 공유 가능. 뒤로가기·스와이프·하드웨어 백 전부 막고 "홈으로 이동" 하나로 통일. 주소가 텍스트로도 표시된다.

11.7 종료

찾기 완료 → 상태 resolved. "자주 다니던 곳" 데이터 삭제. 제보자 전원에게 결과 알림.

11.8 사건 상태

searching → resolved. 세분화된 EXPIRED/CANCELLED/SUSPENDED는 아직 미구현(수동 운영으로 대체).

#12. 분실 알림 — 주변 사용자 경험

12.1 푸시 구성

새 분실 신고 → 같은 동 사용자에게 발송. 알림함 배지는 "아직 안 본 신고가 있나" 기준 — 한 번 열면 다시 안 켜짐.

12.2 상세 화면 (목격자용)

사진, 찾는 중 상태, 견종/성별/나이. 마지막 목격 위치를 지도+텍스트 둘 다로 표시. 경계 경고 배너. "자주 다니던 곳" 히트맵(신고자가 켰을 때만). 하단 CTA 목격했어요.

#13. 목격 제보 플로우

13.1 입력 (앱 사용자)

위치(드래그 가능 지도), 시각(방금/15분전/1시간전/직접), 사진, 메모.

13.2 전달 완료

타임라인·지도에 실시간 반영, 보호자에게 즉시 푸시.

13.3 앱 제보 vs 게스트 제보 구분

sightings.is_guest로 구분. 게스트 제보에는 "?" 아이콘 — 누르면 "외부에서 신고된 건이에요" 설명.

13.4 제보 상태

pending → confirmed. 철회 UI는 아직 없음.

13.5 비회원 게스트 제보 (신규 — 콜드스타트 대응)

  • walk.wouldyou.me/find?case=<id> — 별도 Vercel 사이트. 앱 설치 없이 제보 가능.
  • 위치는 텍스트(자유 입력)만 받는다. 브라우저 GPS 자동입력은 검토 후 폐기 — 폼 작성 위치와 목격 위치가 다를 수 있어서, 틀릴 수 있는 좌표보다 정직한 텍스트가 낫다는 판단.
  • 사진이 있으면 og:image로 카카오톡/당근마켓 공유 미리보기 카드 지원.
  • 원래 Supabase Edge Function으로 만들었으나, 플랫폼이 text/html 응답을 text/plain으로 강제 변환하는 제약이 있어 Vercel로 옮겼다.

#14. 주변 지도

14.1 레이어와 필터

레이어: 분실, 쓰레기통(배타 선택). 분실 레이어에 "내 동네"/"전체보기" 토글(신규) — 기본은 지금 동 기준(알림 대상과 동일), 전체보기는 동 제한 없이 전체(최대 200건)를 보여준다. 쓰레기통은 기존대로 3km 반경.

14.2 분실 핀

주황색 핀. 바텀시트는 모드에 따라 "{동 이름} {count}건" 또는 "전체 {count}건". 동을 못 알아냈으면 빈 목록 대신 "동네를 확인하지 못했어요, 전체보기로 볼 수 있어요" 안내.

14.3 위치 공개

목격 제보의 정확 좌표는 공개 지도에 안 뿌린다.

#15. 기록과 사진

15.1 기록 탭 (구조 변경)

기록 탭 안에 [산책 기록]·[사진] 서브탭. 산책 기록은 목록만(캘린더는 §15.2가 별도로 맡음), 사진은 3열 그리드.

15.2 캘린더 / 전체보기

홈의 "캘린더" → "전체보기"로 월 캘린더 + 통계 + "자주 갔던 곳" 히트맵(전체 기간) 대시보드로 이동.

15.3 사진

삭제해도 연결된 산책 기록은 유지. 스토리지에 파일이 실제로 없는 "유령 사진" 문제는 로드 실패 시점에 존재를 재확인해 삭제하도록 고쳤다.

#16. 마이(내 정보와 설정)

프로필, 반려견 관리, 로그아웃/탈퇴, 신고·차단 관리, 알림 설정(단일 토글), 고객센터, 약관, 공유하기.

#20. 백엔드 아키텍처 (v1.2의 "API 초안" 대체)

v1.2는 전용 REST API 서버를 가정했지만, 실제로는 Supabase 하나로 구현했다.

  • 읽기/쓰기 대부분: PostgREST + RLS 정책으로 직접.
  • 관계 확인이 필요한 쓰기: 테이블 insert 정책을 아예 안 두고 SECURITY DEFINER RPC로만 허용(like_neighbor(), join_group_by_code(), find_walk_neighbors() 등).
  • 크론 작업: pg_cron + pg_net으로 Edge Function 주기 호출, 전용 시크릿(x-cron-secret)으로 인증.
  • 알림 발송: notification_outbox에 쌓고 flush-outbox가 Expo Push API로 발송.
  • 비회원 웹 제보: 별도 정적 사이트(Vercel) + Edge Function이 Supabase REST를 서비스 키로 직접 호출.

#21. RPC 호출 예시 (v1.2 "요청/응답 예시" 대체)

// 하트 주기
await supabase.rpc('like_neighbor', { p_target_id: targetUserId });

// 분실 신고 게시(테이블 insert, RLS: 본인만)
await supabase.from('lost_cases').insert({ owner_id, pet_name, last_seen_lat, ... });

파라미터 이름·타입의 최종 근거는 각 RPC를 정의한 마이그레이션 파일이다.

#22. 비기능 요구사항

목표는 유효하나, 부하·침투 테스트는 사용자 규모가 아직 작아 실측하지 않았다. 실제로 대응한 것: 산책 중 프로세스가 죽어도 headless 재기동 시 상태 복원(§9.5), 좌표 튐·저정확도 필터링, 위경도 델타 60도 초과 시 렌더링 클램프로 네이티브 크래시 방지. 보안: 소셜 로그인 토큰은 SecureStore(Keychain), 관계가 걸린 쓰기는 SECURITY DEFINER 경유(§20).

#23. 예외 및 경계 조건 (실제로 겪고 고친 것)

상황처리
위치 못 잡음기본 좌표로 대체하지 않고 실패 상태를 그대로 표시
서울↔해외처럼 좌표가 크게 벌어진 경로델타 클램프로 지도 크래시 방지
스토리지에 파일 없는 사진로드 실패 시점에 존재 재확인 후 삭제
로그인 직후 세션 지연복구 재시도 후 판단(신규 오인 방지)
산책 중 앱이 죽음스냅샷 복원, 리마인더는 서버 신호로 스킵
신고한 곳과 지금 있는 곳의 동이 다름"내 신고 현황"은 위치·동 무관하게 항상 표시
동을 못 알아냄빈 목록 대신 실패 안내 + 전체보기 유도
이미 활성 분실 신고 있음기존 사건으로 이동(중복 신고 방지)

#24. 분석 이벤트와 KPI

미구현. 이벤트 트래킹 SDK를 아직 붙이지 않았다. 계측 계획은 별도 퍼널 분석 로드맵 참고.

#25. 운영자 도구

전용 웹 콘솔 없음. 신고 검수·콘텐츠 숨김·사용자 제재는 Supabase 대시보드(Table Editor, SQL Editor)로 수동 처리한다.

#26. QA 인수 기준

  • 위치 권한을 "사용 중에만"에서 "항상 허용"으로 올리면, 앱을 다시 열었을 때 배너가 사라지고 실제로 백그라운드 추적이 시작된다.
  • 신고한 위치와 다른 동에 있어도 홈의 "내 분실 신고 현황"이 뜬다.
  • 동네친구/모임에서 하트 버튼을 누르면 채워진 채로 유지되고, 오늘 이미 준 상대는 다시 눌러도 "이미 보냈어요"로만 안내한다.
  • 산책 중 화면을 나가도(다른 탭 이동) GPS 기록이 끊기지 않는다.

#27. 개발 우선순위와 출시 단계 (갱신)

완료(v1.2의 Phase 0~2)

인증, 반려견 등록, 산책 기록(오프라인 복구 포함), 쓰레기통 지도, 분실 신고 4단계, 동 기반 알림, 목격 제보(앱+게스트), 콘텐츠 신고/차단.

완료(v1.2에 없던 것)

동네친구·모임·하트, 개인화 산책 리마인더, 비회원 게스트 제보 웹페이지, 백그라운드 산책 유실 방지.

다음

사용자 규모 확보(무료 채널 기반 로컬 비즈니스 파트너십), 최소 하나의 유료 기능으로 수익화 가설 검증, Android 출시, 분석 이벤트 트래킹 도입.

#28. 출시 전 반드시 확정할 정책

아직 사업/법무 확정이 필요한 항목 — 상세는 정책서 참고.

  1. 서비스 지원 국가·지역(현재 한국어·iOS 우선)
  2. 정확 위치·경로·사진·신고 제보의 보존·삭제 기간(현재 명시적 TTL 없음)
  3. 보호자·제보자 간 연락 방식(현재 앱 내 전달만)
  4. 허위 신고·악성 제보 제재 단계
  5. 미성년자 가입 기준
  6. 경찰·소방·지자체·보호소 안내 문구 및 면책 표현
  7. 공공 쓰레기통 데이터 이용 조건·갱신 주기
  8. 개인정보 사고 대응 담당자·통지 절차

#29. 화면 문구 변수 규칙

#30. 최종 사용자 플로우 요약 (갱신)

평상시

로그인 → 반려견 등록 → 홈 → 산책 시작(FAB) → 경로/사진 기록 → 종료 시 제목·메모·사진 바로 추가 → 하트 획득 애니메이션 → 기록/사진 회고

동네친구·하트 (신규)

산책 → 경로가 겹친 이웃과 자동 매칭 → 친구 탭에서 확인 → 사진 확대 후 하트 → 상대에게 즉시 푸시 → 하루 지나면 다시 줄 수 있음

분실 시 보호자

사이렌 버튼 → 반려견 확인 → 마지막 목격 위치·시각 입력 → 자주 다니던 곳 노출 여부 선택 → 게시(같은 동 자동 계산) → 링크 복사로 외부 공유 → 제보 타임라인 확인 → 찾기 완료

주변 사용자

같은 동 푸시 수신 → 분실 상세(주소 텍스트 포함)·안전 안내 확인 → 목격했어요 → 위치(텍스트)·시각·사진 입력 → 보호자에게 전달

비회원(앱 없음, 신규)

공유된 링크 클릭 → walk.wouldyou.me/find → 반려견 정보 확인 → 목격 위치(텍스트)·시각·메모 입력 → 전송(앱 설치 불필요)

쓰레기통 정보

주변/산책 지도 → 공공데이터 쓰레기통 레이어 → 핀 위치 확인 → 출처·기준일·없어졌어요 누적 수 확인 → 현장에 없으면 없어졌어요 제출
