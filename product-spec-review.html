#우쥬산책 서비스 상세 기획안

문서 버전: v1.2
작성일: 2026-08-15
대상: Product, UX/UI, iOS/Android, Backend, QA, 운영
기준 자료: 제공된 온보딩·산책·분실 신고·목격 제보·사진·기록·주변 지도 화면

#1. 문서 목적

우쥬산책은 반려견과의 일상적인 산책을 기록하고, 공공데이터 기반 쓰레기통 위치를 지도에서 안내하며, 반려견 분실 시 마지막 위치 주변 사용자에게 신속히 알리고 목격 정보를 보호자에게 전달하는 지역 기반 서비스다.

이 문서는 화면 구현에 필요한 값과 상태뿐 아니라 실제 서비스 운영에 필요한 위치·알림·개인정보·신뢰·신고·장애 대응 기준까지 정의한다. 별도 표시가 없는 수치와 정책은 MVP 권장 기본값이며, 운영자 설정값으로 관리한다.

#2. 제품 목표와 원칙

#2.1 목표

  1. 사용자가 별도 학습 없이 2탭 이내로 산책을 시작하게 한다.
  2. 산책 기록에서 생성되는 위치·사진·시설 정보를 일상적 효용으로 돌려준다.
  3. 분실 신고 등록 후 60초 이내에 대상 반경의 알림 발송 요청을 완료한다.
  4. 목격자가 3단계 이내로 위치·시각·사진을 보호자에게 전달하게 한다.
  5. 신고자의 정확한 집 주소나 목격자의 현재 위치가 불필요하게 공개되지 않게 한다.

#2.2 핵심 원칙

  • 긴급 기능 우선: 활성 분실 신고는 홈의 날씨·통계·최근 산책보다 위에 노출한다.
  • 입력보다 확인: 반려견 프로필을 분실 신고서에 자동 채우고, 사용자는 확인·수정만 한다.
  • 최소 공개: 지도에는 근사 위치를 표시하고 정확 좌표는 권한과 목적에 따라 제한한다.
  • 행동 중심 문구: 제보하기보다 목격했어요, 종료보다 찾기 완료처럼 결과가 분명한 CTA를 사용한다.
  • 안전 우선: 목격자에게 접근·추격·포획을 요구하지 않고 거리 확보와 보호자 연락을 안내한다.
  • 판단 가능한 정보 제공: 쓰레기통은 공공데이터와 없어졌어요 누적 수만 제공하고, 이용 가능 여부는 사용자가 판단한다.

#2.3 MVP 범위

  • 카카오/구글 로그인, 필수 약관 동의
  • 반려견 1마리 이상 등록 및 수정
  • 산책 시작·일시정지·재개·종료, 경로·시간·거리·사진 저장
  • 산책 중 공공데이터 기반 쓰레기통 지도 조회 및 없어졌어요 제보 수 확인
  • 분실 신고 생성·게시·갱신·종료
  • 위치 기반 분실 푸시 알림 및 인앱 상세
  • 목격 제보 생성, 보호자 실시간 반영, 결과 알림 구독
  • 사진 모아보기, 산책 기록 목록/상세
  • 주변 분실 지도, 내 활동, 알림·공개 범위·차단 설정
  • 콘텐츠 신고, 운영자 검수/숨김/제재

#2.4 후속 범위

  • 실시간 채팅·전화번호 중계 통화
  • 동물병원·보호소·경찰/지자체 연계
  • AI 사진 유사도 검색
  • 산책 친구, 배지·리워드, 웨어러블 연동
  • 쓰레기통 외 배변봉투함·급수대·반려견 출입 시설

#6.2 필수/선택 동의

  • 필수: 이용약관, 개인정보 수집·이용, 만 14세 이상 확인
  • 선택: 위치 기반 주변 알림, 마케팅 알림
  • 서비스 실행에 필요한 위치 처리는 기능별 명시적 동의를 받고 철회 경로를 나 > 위치·공개 범위에 둔다.

#7. 온보딩 및 반려견 등록

#7.1 로그인

  • 브랜드 메시지: 매일의 산책이 동네를 안전하게.
  • 보조 문구: 걸을수록 쌓이는 기록과, 사라진 순간 가장 먼저 움직이는 이웃들.
  • 로그인 수단: 카카오, 구글. iOS 출시 시 다른 제3자 로그인을 제공하면 Apple 로그인도 함께 지원한다.
  • 최초 로그인 성공 → 약관 동의 → 알림/위치 안내 → 반려견 등록.
  • 기존 사용자 → 토큰 갱신 → 마지막 활성 탭. 진행 중 산책이 있으면 산책 화면 우선 복구.

#8. 홈

#8.1 노출 우선순위

  1. 본인이 진행 중인 분실 신고 또는 산책
  2. 반경 내 활성 분실 알림 배너
  3. 산책 날씨 카드
  4. 이번 주 산책 횟수·총 거리·총 시간
  5. 산책 시작 CTA
  6. 최근 산책 최대 3건

분실 배너에는 {동네명}, {경과시간}, {거리}, {반려견명}을 표시한다. 예: 우리 동네 분실 1건 · 성산동 · 40분 전 · 2.1km 이내. 탭하면 해당 사건 상세 또는 주변 지도 포커스로 이동한다.

#8.2 산책 날씨

  • 표시값: 현재 기온, 강수 여부, 미세먼지/폭염·한파 주의, 한 줄 권장 문구.
  • 위치 미동의/날씨 API 실패 시 현재 날씨를 불러올 수 없어요와 재시도만 표시하며 산책은 막지 않는다.

#9. 산책 기록

#9.1 시작 전

  • 산책 대상 반려견 선택(1마리면 자동 선택)
  • 위치 권한, GPS 활성화, 배터리 절약 모드 영향 확인
  • 산책 시작 탭 시 서버에 walk_session 생성 후 로컬 기록을 동시에 시작한다.
  • 네트워크가 없어도 로컬 UUID로 시작하고 연결 복구 시 동기화한다.

#9.2 산책 중 화면

  • 상단 고정 지표: {elapsed_time}, {distance_km}
  • 지도: 현재 위치, 이동 경로 polyline, 시작점, 사진 촬영 지점
  • 보조 CTA: 쓰레기통 위치 보기
  • 하단 원형 버튼: 일시정지/재개, 종료, 카메라
  • 잠금 화면/다이내믹 아일랜드 지원 시 시간·거리·진행 상태만 노출

#9.3 거리 및 경로 계산

  1. 위도·경도·측정 시각·정확도·속도를 수집한다.
  2. accuracy > gps_accuracy_threshold_m인 점, 비현실적 순간 이동, 오래된 좌표를 제외한다.
  3. 연속 유효점 간 geodesic distance를 합산한다.
  4. 일시정지 구간은 시간·거리에서 제외하되 원본 이벤트는 보존한다.
  5. 지도 표시용 경로는 단순화하되 통계 산출은 원본 유효점으로 계산한다.

#9.4 종료

  • 종료 버튼은 장갑 낀 손도 누르도록 최소 76px 터치 영역을 확보한다.
  • 탭 → 산책을 종료할까요? 확인 → 종료.
  • 결과값: 거리, 총/이동 시간, 평균 속도, 연속 산책 일수, 경로, 사진.
  • 제목 기본값은 {행정동} 산책이며 사용자가 1~30자로 수정 가능하다.
  • 100m 미만 또는 2분 미만 기록은 저장 여부를 확인하고 주간 통계에서 제외 가능하게 한다.
  • 종료 저장 실패 시 로컬에 pending_sync로 유지하고 사용자에게 기록 보존 상태를 알린다.

#9.5 산책 상태

CREATED → ACTIVE ↔ PAUSED → COMPLETING → COMPLETED

예외 상태는 PENDING_SYNC, 사용자 취소는 DISCARDED, 24시간 이상 비정상 지속은 앱 재진입 시 복구/종료 선택을 받는다.

#10. 쓰레기통 지도

#10.1 지도 표현

  • 주변 지도와 산책 중 오버레이에서 쓰레기통 레이어를 토글한다.
  • 지도에는 공공데이터로 수집된 쓰레기통만 표시한다.
  • 사용자는 위치를 추가하거나 기존 위치·유형·설명을 수정할 수 없다.
  • 없어졌어요 제보가 누적되어도 핀을 자동으로 숨기거나 상태를 확정하지 않는다.
  • 핀 클러스터링을 사용하고 확대 시 개별 핀으로 전환한다.

#10.2 시설 상세

  • 거리, 시설 유형, 이용 시간, 주소, 공공데이터 출처와 기준일을 표시한다. 값이 없는 항목은 만들지 않고 정보 없음으로 표시한다.
  • 이동·경로 탐색·외부 지도 앱 연결 기능은 제공하지 않는다. 사용자는 현재 지도에 표시된 핀을 보고 직접 찾아간다.
  • 쓰레기통 상세의 유일한 행동 CTA는 없어졌어요다.
  • 없어졌어요 옆에 누적 제보 수 {removed_report_count}를 표시한다. 0건도 숨기지 않고 없어졌어요 0으로 표시한다.
  • 안내 문구: 공공데이터 기준 위치예요. 없어졌다는 제보가 {removed_report_count}건 있어요. 현장 상황을 확인해 주세요.
  • 제보 수는 사실 확정이나 운영자 검증 결과가 아니라 사용자 참고 정보임을 명시한다.

#10.3 없어졌어요 제보

  • 탭 시 이 위치의 쓰레기통이 보이지 않나요? 확인창을 노출한다.
  • 확인 CTA는 없어졌어요, 취소 CTA는 취소로 한다.
  • 사진·메모·현재 위치 등 추가 정보는 받지 않는다.
  • 로그인 사용자만 제출할 수 있으며 동일 시설에는 24시간에 1회만 제출할 수 있다.
  • 제출 완료 즉시 누적 수를 1 증가시키되, 네트워크 재시도와 연속 탭은 idempotency key로 중복 반영을 막는다.
  • 사용자가 잘못 누른 경우 완료 토스트에서 실행 취소를 제공한다. 실행 취소 가능 시간은 10초다.

#10.4 데이터 갱신 및 운영

  • 모든 핀은 source=PUBLIC_DATA이며 데이터셋명·제공기관·기준일·원본 식별자를 저장한다.
  • 공공데이터 갱신 시 원본 식별자를 우선 사용하고, 식별자가 없으면 좌표와 주소를 이용해 기존 핀을 매칭한다.
  • 공공데이터에서 삭제된 시설은 다음 동기화 후 지도에서 제거한다. 사용자 제보 수만으로는 제거하지 않는다.
  • 없어졌어요 누적 수는 지도와 상세에 그대로 표시한다. 별도의 확인됨, 검증 중, 오류 상태로 해석하지 않는다.
  • 운영자는 명백한 중복 핀이나 공공데이터 오류를 관리 화면에서 비노출 처리할 수 있으나, 사용자에게 검증 완료로 표현하지 않는다.

#11. 분실 신고 — 보호자 플로우

#11.1 진입

  • 홈 활성 분실 배너, 반려견 프로필, 나 > 내 분실 신고에서 진입한다.
  • 첫 화면에서 긴급 기능의 공개 범위와 안전 안내를 설명한다.
  • 앱이 경찰 신고나 구조기관 접수를 대체하지 않음을 명시한다.

#11.2 1단계: 반려견 확인

  • 등록된 프로필 카드 선택, 다견 가정은 1마리 선택.
  • 대표 사진·이름·견종·성별·나이·체중·특징·착용품을 자동 채운다.
  • 분실 당시 모습과 다른 경우 추가 사진 최대 5장과 특징을 덧붙일 수 있다.
  • 공개 전 연락 수단은 앱 내 전달을 기본으로 하며 전화번호는 기본 비공개다.

#11.3 2단계: 마지막 목격 정보

필드 키화면명필수기본/검증
last_seen_lat/lng마지막으로 본 곳Y현재 GPS, 검색 또는 지도 핀 이동
last_seen_address주소자동역지오코딩, 공개 시 동/랜드마크 수준
last_seen_at언제 사라졌나요?Y방금/30분 전/1시간 전/직접 입력, 미래 불가
direction_code이동 방향N8방향 + 모름
wearing_items당시 착용N목줄/인식표/하네스/옷 등

직접 입력은 날짜와 시각을 모두 받는다. GPS 정확도가 낮으면 정확도 원을 표시하고 핀 확인을 요구한다.

#11.4 3단계: 알림 범위와 게시

  • 선택 반경: 1/3/5km, 기본 3km.
  • 예상 도달 대상:

    • - 이 지역 산책 사용자 약 {nearby_walker_count}명 - 최근 7일 활동 사용자 {recent_active_count}명

  • 이 숫자는 추정치이며 중복·알림 거부 사용자를 제외한 실제 발송 수와 다를 수 있음을 표시한다.
  • 지금 게시하기 탭 → 최종 요약 확인 → 사건 생성과 알림 발송 작업 등록.
  • 게시 즉시 공개: 대표/추가 사진, 이름, 견종, 외형, 마지막 목격 근사 위치·시각, 안전 안내.
  • 비공개: 보호자 실명, 전화번호, 정확한 집 주소, 계정 식별자.

#11.5 수신 대상 계산

다음 조건을 모두 만족하는 사용자에게 발송한다.

  1. 분실 알림 동의 및 OS 푸시 허용
  2. 차단 관계가 없고 계정이 정상 상태
  3. 최근 30일 내 산책 경로 또는 사용자가 설정한 생활권이 알림 반경과 교차
  4. 동일 사건의 최초 알림을 받지 않았거나, 중대한 갱신 푸시 조건에 해당

단순 현재 위치만으로 대상을 고정하지 않는다. 백그라운드 위치를 지속 추적하지 않고, 사용자가 제공한 생활권 또는 최근 산책의 비식별 공간 인덱스를 사용한다. 발송 대상 산출 스냅샷과 발송 결과를 감사 로그로 남긴다.

#11.6 진행 중 사건 관리

  • 헤더: 보리를 찾는 중, 경과 시간, 제보 수
  • 지도: 마지막 목격점과 제보 지점 타임라인
  • 제보 카드: 시각, 근사 위치, 사진, 메모, 확인 상태
  • 보호자 액션:

    • - 확인 필요 → 확인함/관련 없음 - 마지막 목격 위치 갱신 - 알림 반경 재발송(과도한 발송 제한) - 사건 공유 링크 생성 - 찾기 완료

제보 좌표 사이의 선은 이동 경로로 단정하지 않고 시간순 목격 정보로 표현한다.

#11.7 종료

  • 종료 사유: 반려견을 찾음, 보호소/기관에서 확인, 오등록, 기타.
  • 찾은 시각, 도움된 제보 최대 3건을 선택 가능.
  • 완료 화면: {pet_name}가 돌아왔어요, 총 소요 시간, 제보 수, 알림 도달 수.
  • 활성 지도와 신규 제보 기능은 즉시 닫고, 공개 사건 데이터는 30분 후 캐시에서 제거한다.
  • 제보자에게 결과 알림을 보내되 보호자의 상세 위치·연락처는 공유하지 않는다.

#11.8 사건 상태

DRAFT → ACTIVE → FOUND | EXPIRED | CANCELLED | SUSPENDED

  • ACTIVE: 지도 노출·알림·제보 가능
  • FOUND: 찾기 완료, 제보 불가
  • EXPIRED: 14일 미갱신 자동 종료, 보호자가 재활성 가능
  • CANCELLED: 오등록/보호자 취소
  • SUSPENDED: 운영 정책 위반으로 비공개

동일 반려견의 ACTIVE 사건은 1건만 허용한다. 게시 경쟁 요청은 idempotency key로 중복을 막는다.

#12.1 푸시 구성

  • 본문: {area_name} · {distance_text} · {breed} · {feature_short} · {elapsed_text}

#12.2 상세 화면

  • 사진, 찾는 중 상태, 거리, 경과 시간
  • 이름·견종·성별·나이·외형/착용 특징

완료/만료 사건의 딥링크 진입 시 더 이상 제보받지 않는다는 상태와 완료 시각만 보여준다.

#13. 목격 제보 플로우

#13.1 입력

필드 키화면명필수기본/검증
seen_lat/lng목격 위치Y현재 위치, 지도에서 수정 가능
seen_at언제 봤나요?Y방금/5분 전/15분 전/직접 입력
direction_code이동 방향N8방향 + 멈춰 있음 + 모름
photos사진N최대 3장, EXIF 위치는 서버 저장 전 제거
memo메모N최대 300자
result_subscription이 아이 소식 받기N기본 ON, 언제든 해제 가능

필수 입력을 완료하면 보호자에게 전달이 활성화된다. 네트워크 실패 시 암호화된 로컬 임시 저장 후 명시적 재전송을 제공하며, 오래된 제보가 자동 전송되지 않게 30분 후 재확인을 요구한다.

#13.2 전달 완료

  • 보호자에게 전달됐어요
  • 위치(랜드마크/도로명 축약), 시각, 사진 장수를 요약해 신뢰를 준다.
  • 경고: 직접 붙잡으려 하지 말고 위험하면 112/119 등 적절한 기관에 연락하도록 안내한다.
  • 완료 후에도 사건 결과 알림 토글을 변경할 수 있다.

#13.3 보호자 측 반영

  • 새 제보는 사건 타임라인과 지도에 실시간 추가한다.
  • 보호자 푸시: {area_name}에서 새 목격 제보가 도착했어요.
  • 다른 일반 사용자에게는 제보자의 정확 좌표·사진을 즉시 재배포하지 않는다. 보호자가 확인함 처리한 제보만 근사 위치로 공개 지도에 반영 가능하다.
  • 동일 사용자·위치·시각의 반복 제출은 중복 후보로 묶는다.

#13.4 제보 상태

SUBMITTED → DELIVERED → REVIEWED_RELEVANT | REVIEWED_IRRELEVANT → WITHDRAWN | MODERATED

제보자는 전달 전 수정 가능, 전달 후에는 정정 제보 또는 철회만 가능하다. 감사와 분쟁 대응을 위해 수정 이력을 보존한다.

#14. 주변 지도

#14.1 레이어와 필터

  • 레이어: 분실, 쓰레기통
  • 분실 필터: 거리, 게시 시각, 견종/크기, 찾는 중만
  • 시설 필터: 유형, 검증 상태, 최근 확인
  • 현재 위치는 파란 점 하나로 표시하며 다른 사용자의 위치는 표시하지 않는다.

#14.2 분실 핀

  • 주황색 핀, 이름 라벨은 확대 단계에서만 표시
  • 바텀시트: 우리 동네 {count}건, 사진, 이름·견종, 근사 거리, 경과 시간, 제보 수
  • 0건일 때: 오늘 우리 동네는 조용해요와 쓰레기통 레이어/산책 시작을 안내한다.

#14.3 위치 공개

  • 신고자의 마지막 목격 위치는 공개 지도에서 200m 격자 또는 랜드마크 수준으로 흐림 처리한다.
  • 제보자의 현재 위치와 이동 경로는 공개하지 않는다.
  • 보호자는 사건 해결에 필요한 기간에만 정확 제보 위치를 열람한다.
  • 사용자는 나 > 위치·공개 범위에서 생활권 기반 알림 사용을 끌 수 있다.

#15. 기록과 사진

#15.1 기록 목록

  • 최신순 무한 스크롤, 월 단위 구분
  • 카드: 썸네일 지도, 제목, 날짜, 거리, 시간
  • 탭 시 상세로 이동
  • 삭제는 확인 후 소프트 삭제, 30일 내 복구 가능

#15.2 기록 상세

  • 경로 지도, 거리, 시작/종료 시각, 지역, 시간, 평균 속도, 연속 기록
  • 연결 사진, 사진 촬영 지점(사용자가 허용한 경우)
  • 제목 수정, 사진 추가/삭제, 공유 이미지 생성
  • 공개 공유물은 시작·종료점 주변을 흐림 처리한다.

#15.3 사진 목록

  • 전체 사진을 3열 그리드로 노출, +로 업로드
  • 상세 팝업: 이미지, 촬영/업로드 날짜, 연결 산책 제목과 통계
  • 산책과 연결되지 않은 사진은 업로드 날짜만 표시
  • 삭제 시 연결 산책 자체는 유지한다.

#16. 내 정보와 설정

  • 프로필: 닉네임, 활동 지역, 가입 일수
  • 활동 지표: 총 산책, 누적 거리, 목격 제보 수
  • 메뉴:

    • - 반려견 관리 - 내 제보 기록 - 내 분실 신고 - 알림 설정 - 위치·공개 범위 - 차단한 사용자(0건이어도 노출) - 고객센터/정책/버전 - 계정 탈퇴

알림 설정은 주변 분실, 내 사건 새 제보, 사건 결과, 산책 리마인드, 서비스 안내를 각각 제어한다. 긴급 알림도 사용자의 명시적 선택을 존중하며 강제 활성화하지 않는다.

#17. 콘텐츠 신고와 차단

#17.1 신고 대상

  • 분실 사건, 목격 제보, 시설 정보, 공유 이미지, 사용자

#17.2 신고 사유

  • 허위 또는 무관한 정보
  • 타인의 사진 도용
  • 욕설·괴롭힘
  • 금전 요구·사기 의심
  • 개인정보 노출
  • 기타

상세 설명은 선택이며 최대 500자. 이 사용자 차단 토글을 같은 화면에서 제공한다. 접수 후 24시간 이내 검토를 안내하며 사건의 긴급성·개인정보 위험에 따라 우선순위를 높인다.

#17.3 자동/수동 조치

  • 개인정보 패턴·노골적 금전 요구·악성 링크는 게시 전 경고 또는 보류한다.
  • 신고 누적만으로 사용자 계정을 영구 정지하지 않는다.
  • 긴급한 개인정보 노출은 콘텐츠를 임시 숨기고 운영자가 복구/삭제한다.
  • 운영 조치는 사유·담당자·시각·이전 상태를 감사 로그에 남긴다.

#19.2 위치 저장 원칙

  • 원본 좌표와 공개 좌표를 분리한다.
  • DB에는 공간 인덱스를 적용하고 반경 검색은 서버에서 수행한다.
  • 원본 위치는 전송/저장 암호화, 접근 권한 분리, 관리자 열람도 사유 기록.
  • 산책 경로 원본의 기본 보존 기간은 계정 유지 기간으로 하되 사용자가 개별 삭제 가능하게 한다.
  • 목격 정확 좌표는 사건 종료 후 30일 이내 삭제 또는 비가역 격자화한다.
  • 알림 대상 산출용 생활권은 원본 경로가 아니라 공간 셀 집합으로 별도 보관한다.

#22. 비기능 요구사항

#22.1 성능

  • 홈 첫 콘텐츠 표시 p75 1.5초 이내(캐시 포함)
  • 지도 이동 후 핀 갱신 p75 1초 이내
  • 사건 게시 API p95 2초 이내, 알림 작업 큐 등록 5초 이내
  • 이미지 업로드 진행률·취소·재시도 제공
  • 1만 개 이상 핀을 클라이언트에 일괄 반환하지 않고 서버 클러스터링 적용

#22.2 안정성

  • 산책은 네트워크 단절·앱 종료·화면 잠금 후에도 복구 가능해야 한다.
  • 좌표 업로드는 배치 단위 checksum과 마지막 승인 sequence로 유실/중복을 방지한다.
  • 사건 상태 변경과 알림 작업 생성은 트랜잭션 또는 outbox 패턴으로 결합한다.
  • 찾기 완료 후 늦게 도착한 제보 요청은 409와 종료 상태를 반환한다.

#22.3 보안

  • 소셜 토큰 서버 검증, access/refresh token 분리와 회전
  • 객체 단위 권한 검사(BOLA 방지)
  • 업로드 파일 MIME·확장자·악성 파일 검사, EXIF 제거
  • 로그에 토큰·정확 좌표·전화번호·자유 입력 원문을 남기지 않음
  • 관리자 기능 MFA와 역할 기반 권한, 모든 민감 조회 감사
  • API rate limit과 사건/제보/신고 생성 어뷰징 탐지

#22.4 접근성

  • 텍스트 대비 WCAG AA, 색상 외 아이콘/라벨로 상태 구분
  • 터치 영역 최소 44×44pt
  • 동적 글자 크기, VoiceOver/TalkBack 라벨
  • 지도 정보는 접근 가능한 목록 보기로도 제공
  • 긴급 CTA는 읽기 순서상 앞쪽에 배치

#24. 분석 이벤트와 KPI

#24.1 핵심 이벤트

  • login_completed
  • pet_registration_started/completed
  • walk_started/paused/resumed/completed/sync_failed
  • trash_layer_opened, trash_bin_detail_opened, trash_bin_removed_reported/undone
  • lost_case_started/step_completed/published/resolved
  • lost_alert_queued/delivered/opened
  • sighting_started/submitted/reviewed
  • content_report_submitted

공통 속성: event_id, user_id_hash, session_id, app_version, os, occurred_at, screen, network_type. 분석 도구에는 정확 좌표, 반려견 이름, 자유 문구, 사진 URL을 보내지 않는다.

#24.2 핵심 KPI

  • 가입 → 반려견 등록 완료율
  • 주간 산책 기록 사용자 수와 산책 완료율
  • 산책 1회당 GPS 기록 성공률
  • 쓰레기통 상세 열람률, 없어졌어요 제보율, 제보 수 분포
  • 분실 신고 시작 → 게시 완료율과 중앙 소요 시간
  • 게시 → 첫 알림 발송, 첫 열람, 첫 제보까지의 시간
  • 알림 열람률, 상세 → 제보 시작/완료 전환율
  • 해결 사건 비율과 보호자가 도움됐다고 선택한 제보 비율
  • 허위 사건/제보 신고율, 운영 SLA 준수율

찾은 비율은 앱의 인과 효과로 과장하지 않고, 신고 등록 건 중 상태가 FOUND로 종료된 비율로 정의한다.

#25. 운영자 도구

  • 사건 검색: ID, 상태, 지역, 게시 시각, 사용자 상태
  • 사건 상세: 공개/원본 정보 분리, 알림 발송 결과, 제보 타임라인
  • 콘텐츠 조치: 사진/문구/좌표만 부분 숨김, 사건 전체 중지, 복구
  • 사용자 조치: 경고, 기간 제한, 영구 정지, 이의제기 처리
  • 시설 관리: 중복 병합, 위치 수정, 소스 구분, 숨김/복구
  • 신고 큐: 위험도·긴급성·접수 시간 정렬, SLA 타이머
  • 감사 로그: 운영자와 시스템 작업을 append-only로 보존

정확 좌표 열람은 기본 화면에서 마스킹하고, 업무 사유 선택 후에만 제한 시간 동안 표시한다.

#26. QA 인수 기준

#26.1 산책

  • 앱이 백그라운드/잠금 상태가 되어도 허용된 OS 조건에서 경로가 이어진다.
  • 일시정지 동안 시간과 거리가 증가하지 않는다.
  • 동일 GPS 배치를 재전송해도 거리가 중복 합산되지 않는다.
  • 종료 저장 실패 후 앱 재실행 시 기록을 복구할 수 있다.

#26.2 분실 신고

  • 필수 반려견·위치·시각·반경 없이는 게시할 수 없다.
  • 공개 화면에 보호자 실명·전화번호·정확 집 주소가 나타나지 않는다.
  • 동일 반려견의 활성 사건이 중복 생성되지 않는다.
  • 찾기 완료 즉시 신규 제보와 재발송이 차단된다.

#26.3 알림/제보

  • 반경·동의·차단 조건에 맞는 사용자만 대상이 된다.
  • 알림 딥링크가 정확한 사건과 현재 상태를 연다.
  • 제보 제출 후 보호자 화면에 표시되고 발송 결과가 기록된다.
  • 사건 종료 직전/직후의 경쟁 요청에서도 제보와 알림 상태가 일관된다.

#26.4 쓰레기통

  • 지도 viewport 밖 데이터는 불필요하게 내려받지 않는다.
  • 위치 추가·정보 수정·있어요 UI가 노출되지 않는다.
  • 상세에 공공데이터 출처·기준일과 없어졌어요 누적 수가 표시된다.
  • 동일 사용자의 24시간 내 중복 제보와 네트워크 재시도로 인한 중복 집계가 차단된다.
  • 제보 수가 증가해도 핀이 자동으로 숨겨지지 않는다.
  • 공공데이터 갱신에서 삭제된 핀만 정책에 따라 제거된다.

#26.5 접근성과 개인정보

  • 화면 읽기 도구만으로 분실 상세와 제보 완료가 가능하다.
  • 공개 공유 이미지에서 시작·종료점이 흐림 처리된다.
  • 사진 업로드 후 공개 파일에서 EXIF 위치 정보가 제거된다.
  • 계정/기록 삭제와 동의 철회가 설정에서 가능하다.

#27. 개발 우선순위와 출시 단계

#Phase 0 — 기반

  • 인증, 사용자/반려견, 동의·권한, 지도 SDK, 이미지 파이프라인
  • 위치 데이터 보안·공개 좌표 정책, 운영자 기본 권한

  • 부하/침투/권한/위치 개인정보 테스트

  • 파일럿 지역 운영 후 전국 확장

#28. 출시 전 반드시 확정할 정책

아래 항목은 디자인/개발 중 임의 결정하지 않고 사업·법무·운영 책임자가 승인해야 한다.

  1. 서비스 지원 국가·지역과 지도/날씨/푸시 공급자
  2. 정확 위치, 산책 경로, 사진, 신고/제보의 보존·삭제 기간
  3. 보호자와 제보자 사이 연락 방식(앱 내 전달만인지, 번호 중계 허용인지)
  4. 분실 알림 반경과 재발송 횟수, 조용한 시간 예외
  5. 허위 신고와 악성 제보의 제재 단계 및 이의제기 절차
  6. 미성년자 가입 기준과 법정대리인 동의 필요 여부
  7. 경찰·소방·지자체·보호소 안내 문구 및 긴급 상황 면책 표현
  8. 공공 쓰레기통 데이터의 이용 조건·갱신 주기·출처 표기
  9. 사용자 생성 사진과 공유 이미지의 이용 범위
  10. 개인정보 침해·위치 정보 오발송 등 사고 대응 담당자와 통지 절차

#29. 화면 문구 변수 규칙

  • 사람에게 보이는 시간: {elapsed_text} → 40분 전, 2시간 전, 어제
  • 거리: {distance_text} → 1km 미만은 850m, 이상은 1.2km
  • 행정구역: {area_name} → 공개 시 최소 동 수준, 상세 주소는 권한별 제한
  • 수량: {report_count}, {sighting_count}, {recipient_count}는 서버 확정값과 추정값을 구분
  • 반려견: {pet_name}, {breed_name}, {sex_age_text}, {feature_short}
  • 상태: 찾는 중/찾았어요/종료됨/운영 검토 중

모든 동적 문구는 서버 원문 조합이 아니라 클라이언트 localization key와 변수로 렌더링한다. 숫자·날짜·거리 단위는 locale에 맞추고, 빈 값일 때 구분점(·)이 중복 노출되지 않게 한다.

#30. 최종 사용자 플로우 요약

#평상시

로그인 → 반려견 등록 → 홈 → 산책 시작 → 경로/사진 기록 및 쓰레기통 위치 조회 → 산책 종료 → 기록/사진 회고

#분실 시 보호자

분실 신고 진입 → 반려견 확인 → 마지막 목격 위치·시각 입력 → 알림 반경 확인 → 게시 → 제보 타임라인 확인 → 찾기 완료 → 결과 알림

#주변 사용자

위치 기반 푸시 수신 → 분실 상세·안전 안내 확인 → 목격했어요 → 위치·시각·사진/메모 입력 → 보호자에게 전달 → 결과 알림

#쓰레기통 정보

주변/산책 지도 → 공공데이터 쓰레기통 레이어 → 핀 위치 확인 → 출처·기준일·없어졌어요 누적 수 확인 → 사용자가 직접 찾아가 이용 가능성 판단 → 현장에 없으면 없어졌어요 제출
